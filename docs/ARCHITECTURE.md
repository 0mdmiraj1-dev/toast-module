# Native application and SystemUI architecture

App package com.s9encryptor.strongtoastextended owns signature permission com.s9encryptor.strongtoastextended.permission.CONTROL and requests it. SystemUI dynamically registers a package-scoped CONTROL receiver requiring that sender permission (RECEIVER_EXPORTED on API33+). Ordinary third party applications cannot acquire the permission. No exported root service/provider, world-writable file, unprotected command receiver, or background root daemon.

All app command data travels as bounded structured Bundle primitives, with protocolVersion1, requestId UUID, monotonic sequence, and private ResultReceiver reply. Explicit setPackage(com.android.systemui). SystemUI main Handler validates command, bounded text/color/style/duration/icon/settings, and sequence before mutation. GET_CURRENT_STATE/subscription return real module capabilities, native controller availability, original countdown/expiry deadlines, actual native visibility, panel/deferred state, and session/revision. Private ResultReceiver Binder is a capability passed only through the authenticated receiver, never exposed in an exported app component. Reject old mutating sequence; queries must not replace generation state. Send replies asynchronously to avoid blocking main on an unavailable app callback. One active subscription per app, expire/unsubscribe when app backgrounds; SystemUI owns effects/timing independently.

The root bootstrap is separate. RootManager detects su without requesting permission, and first privileged operation launches a packaged generated Java DEX via supported su. No user text enters shell: fixed startup only, subsequent bounded JSON lines on private stdin/stdout. Request root UID0 normally; handle denial and timeouts without auto-reprompt. Reuse process during short bootstrap and close at idle/background.

Native controller normally captured through MIUIStrongToastControl constructors. If unavailable, app sends PREPARE_ROOT_BOOTSTRAP over the signature channel with a cryptographic random nonce; module stores one bounded one-use nonce for at most15s. Root helper then invokes the already-working private StatusBarManager.setStatus(1,strong_toast_action,Bundle) with s9_bootstrap_nonce and callback Binder. Existing setStatus hook consumes only the valid prepared nonce, captures p.thisObject, and acknowledges through callback. Helper verifies callback calling UID equals PackageManager-resolved SystemUI UID. Bootstrap cannot start/stop an arbitrary toast, and unknown nonce is rejected. This avoids relying on undocumented Xiaomi private Binder permission enforcement for command authorization. Never use pm path.

After bootstrap, every normal UI action uses signature IPC directly; no new su/root process per timer tick, state update, panel check or restoration. App reconnects with GET_CURRENT_STATE on launch/resume. If SystemUI restarts, mark disconnected/no active state until a new signed reply; never silently restart an expired previous timer.

The Kotlin app uses MVVM, StateFlow and a single DataStore-backed repository. Production construction always selects NativeController; fake transports exist only under test sources. The foreground UI derives remaining time from SystemUI elapsed deadlines. No app service keeps the status alive. App process death only removes callbacks; SystemUI process death removes the in-memory native session and invalidates the module Binder token.

NativeTextLayout binds once per native view, records baseline properties and listens for text/layout changes. It computes the actual right-icon boundary, measures styled glyph advance and bounds, reserves overhang padding, and preserves native marquee for overflow. Reconciliation is coalesced and fingerprinted, zero-width retries are bounded, and all listeners/baseline changes are released on detach or effect cleanup. It never alters input text or shrinks its font.

The retained restoration state uses generation fencing, original elapsed deadlines, finite native replay failures and native panel state checks. Screen-wake reconciliation catches deadlines that elapsed during deep sleep. Visual pause releases the TextView while independent timer completion/expiry jobs remain scheduled; Stop cancels recovery, timers, shake and owned vibration before requesting native hiding. Device policy may suppress vibration.

All private firmware access is guarded. Capabilities describe hook registration, controller readiness and readable visibility separately; none implies actual device compatibility. Use the target-phone checklist for ROM-dependent behavior.
